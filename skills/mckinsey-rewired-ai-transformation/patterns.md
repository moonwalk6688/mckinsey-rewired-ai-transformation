# Rewired 方法库：将六项能力连成转型闭环

本文件是从书中概念整理出的操作步骤。案例数据不能直接外推。

## 1. 选择业务领域（第 1–5 章）
高管先统一转型理由、价值目标和可投入资源。把端到端客户或员工旅程分成领域，画当前流程、损失与可能的技术杠杆。选少数具有可验证价值的领域，制定业务负责人主导的路线图。AI 用例要连接流程的输入、决策、执行和结果。

## 2. 配齐领导与人才（第 6–11 章）
指定 CEO 赞助、业务域负责人、技术和数据负责人。盘点内部工程、产品、设计、数据、风险能力；给产品/平台岗位长期职业路径。对 Agent 项目明确人负责的意图、异常、审批、质量与新人训练。

## 3. 设计运营模型（第 12–16 章）
从能真正上线的跨职能团队起步；按战略选择数字工厂、域与平台或企业更广范围的模型。画一页域、平台、专业章及其系统、人员和预算。写清决策权、持续拨款、季度业务评审、风控前置与工具连接。分波次孵化、动员、成熟。

## 4. 建共享技术与数据底座（第 17–29 章）
按业务阻碍程度排序 API、工程、AI 和数据平台投资。优先构建真实用例会用到的接口、数据产品、评测、日志及权限护栏。平台作为内部产品运营，追踪复用、开发者体验、单位成本与服务等级。老系统逐步现代化，避免一刀切迁移。对 Agent 分解任务，明确权限、人工监督和持续评测。

## 5. 让方案被采用并复制（第 30–31 章）
用户和领域专家在构建之初参与。改造上下游流程、培训、激励与现场支持。明确复制单元，将共用模块和本地配置分开，预算支持中央维护与本地部署。按每个单元的价值、差异和准备度定波次。

## 6. 衡量并纠偏（第 32–35 章）
把财务/客户结果、过程 KPI、团队 OKR、采用与风险连成价值树，设基线。阶段门评估是否扩大投入；转型办公室主动清障。定期复核成本、人才、平台和数据产品质量，必要时调整目标、路线或负责人。文化通过速度、责任、证据和开放的日常行为形成。

## 输出转型诊断时
按“目标与基线→六项能力现状→前三个制约因素→90 天行动→负责人/指标→风险与待验证假设”给出。对书中案例、作者主张和本技能的应用推演分别标注。
